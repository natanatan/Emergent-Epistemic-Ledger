# Roadmap

Milestones from the implementation specification v0.1. Checked items are
implemented and covered by tests (`cargo test`) or by `examples/walkthrough.sh`.

## Phase 0: Documentation

- [x] `ARCHITECTURE.md`: crate boundaries and dependency direction
- [x] `ROADMAP.md`
- [x] `docs/decisions.md`: every underspecified decision
- [x] Threat model (`docs/threat-model.md`)
- [x] Protocol schemas (`schemas/`, generated by `eel schema`)
- [x] SQLite migration plan (`crates/eel-storage/migrations/`)

## Phase 1: Cryptographic core

- [x] Canonical serialization (`CanonicalSerialize`): sorted keys, UTF-8, NFC, integers, no floats, no whitespace
- [x] BLAKE3 event ids; SHA-256 for external artifact compatibility
- [x] Ed25519 identities and signatures
- [x] `eel identity create` / `eel identity show`
- [x] Event validation (schema version, type/payload match, signature, author key)
- [x] Tests: same object ⇒ same hash (byte for byte); mutation ⇒ different hash; valid signature accepted; invalid rejected

## Phase 2: Ledger

- [x] Append-only event log
- [x] Deterministic Merkle tree over event ids
- [x] Blocks with previous hash, events root, state root, proposer and signature
- [x] State root
- [x] SQLite storage with migrations; append-only enforced by triggers
- [x] Tests: same events ⇒ same Merkle root; same ledger ⇒ same state root; historical state reconstructs

## Phase 3: Ontology

- [x] Claims with versions and procedural statuses
- [x] Revisions that keep every prior version
- [x] Explicit edges with originating events
- [x] Evidence and retraction; objections and replies
- [x] Replications
- [x] Branches with common ancestry, isolation and independent reconstruction
- [x] Tests: revision preserves prior version; branch preserves ancestry; dependency traversal deterministic; superseded claim queryable

## Phase 4: Trust layer

- [x] Configuration-driven genesis validator registry
- [x] Domain restrictions and activity windows
- [x] Validation events (procedural only; never set `SUPPORTED`)
- [x] Canonicalization proposals as separate objects, with a configurable rule
- [x] `ValidatorAdmissionPolicy` with `GenesisOnlyAdmissionPolicy`
- [x] `ReputationProvider` with `NullReputationProvider`
- [x] Tests: in-domain accepted; out-of-domain rejected; one validator cannot satisfy a two-validator rule

## Phase 5: Research and simulation

- [x] Research requests
- [x] Support commitments in development units (three pools)
- [x] Research result submissions; credit regardless of outcome direction
- [x] Deterministic integer graph simulator with the six specified metrics
- [x] Replay verification (`eel sim verify`, `SIMULATION_VERIFY`)
- [x] Simulation results attached to claims as evidence
- [x] Tests: same seed ⇒ same hash; same metrics across processes; modified ruleset ⇒ new hash; fabricated result fails replay

## Interfaces

- [x] REST API with every endpoint in the specification; OpenAPI at `/openapi.yaml`
- [x] `eel` CLI with every command in the specification
- [x] `eel-node start`

## Success criteria (specification §43)

- [x] 1. Two researchers generate independent identities
- [x] 2. One creates a claim
- [x] 3. Another submits an objection
- [x] 4. The claim is revised without destroying history
- [x] 5. Both create competing branches
- [x] 6. Genesis validators validate evidence within domain constraints
- [x] 7. A research request is created
- [x] 8. Simulated support commitments are attached
- [x] 9. A deterministic simulation produces a result
- [x] 10. Independent validators replay that result
- [x] 11. The result becomes evidence for or against a claim
- [x] 12. All actions remain permanently queryable
- [x] 13. Three independent nodes reconstruct identical ontology state from the same event history

## Deferred (not to be implemented in v0.1)

Real cryptocurrency, token transfers, interest, staking contracts, DAO voting,
proof-of-stake, proof-of-work or proof-of-useful-work consensus, production
BFT networking, IPFS, ORCID and DOI integration, zero-knowledge proofs, AI
agents, global reputation, financial prediction markets.
